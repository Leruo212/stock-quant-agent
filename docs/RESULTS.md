# 复现报告

本文件记录所有数字的来源、方法与偏差。每张表都能用文末的命令重跑出来。

环境：macOS (Apple Silicon)，Python 3.13.12，PyTorch 2.15.0，CPU 训练（无 GPU），
pandas 3.1.1，Optuna 4.x。全流程本地耗时约 3 分钟。

---

## 1. 数据

| 项目 | 取值 |
|---|---|
| 股票池 | A 股市值前 300（2026-11-08 快照，剔除 ST / 退市名称） |
| 可用标的 | 285（剔除上市不足 250 个交易日的） |
| 区间 | 2020-02-20 → 2026-10-28 |
| 行数 | 435,702 |
| 复权 | 前复权（qfq） |
| 字段 | date, open, close, high, low, volume |
| 来源 | 腾讯 `web.ifzq.gtimg.cn`（日线主源）→ 新浪 `CN_MarketData`（兜底）→ 东方财富（三级） |
| 基准 | 沪深300（000300），1023 根日线，2022-08-16 → 2026-11-06 |

**关于股票池的口径。** 原论文用「沪深300 成分股中上市早于研究周期的 187 只」。
这里没有取历史时点的成分股，而是取"今天的市值前 300"。这个替代引入了**幸存者偏差**：
能活到 2026 年还留在前 300 的公司，在 2020–2024 期间的表现天然好于当时的真实成分股。
第 4 节用等权持有曲线把这个偏差量化为 +28%/年。

这不能用"数据不好拿"糊过去——它是本项目最严重的方法缺陷，必须读的人先知道。

**关于数据源的稳定性。** 开发过程中东方财富的 `push2` 集群在被连续请求三次后开始返回
连接重置（`RemoteDisconnected`），腾讯在约 900 次请求后返回 501。所以取数层做了三级 fallback
并强制落盘 parquet：一旦缓存建立，全链路零网络请求。这不是过度设计，是被打过两次之后的必需品。

## 2. 特征与标签

9 维特征（`stationary9`），全部是无量纲比值或收益率——因为要把 285 只股票混在一个 batch 里训练，
价格水平本身没有可比性：

| 特征 | 定义 | 对应论文表 3-2 |
|---|---|---|
| `ret1` | 日收益率 | 收盘价（一阶差分） |
| `gap` | 隔夜跳空 `(open - prev_close) / prev_close` | 开盘价 |
| `hl_range` | `(high - low) / close` | 最高 / 最低价 |
| `atr14` | 14 日 ATR / close | 波动指标 ATR |
| `vol_ratio` | 成交量 / 5 日均量 − 1 | 成交量 |
| `ma5_ratio` | close / MA5 − 1 | 重叠指标 MA5 |
| `ma10_ratio` | close / MA10 − 1 | MA10 |
| `ma30_ratio` | close / MA30 − 1 | MA30 |
| `rsi6` | RSI6 / 100 − 0.5 | 超买超卖 RSI6 |

论文表 3-2 列了 15 个以上指标（含 BBANDS、ADX、CCI、KDJ），但正文说输入是 9 维。
差额无法从论文中还原，这里选了覆盖"量价 + 均线 + 波动 + 超买超卖"四类的 9 个。备选的 `raw9`
（原始 OHLCV + MA + 原始 RSI）保留在 `FeatureConfig.feature_set` 里，可用于对比。

标签：`(close[t+7] / close[t]) - 1`，在 ±20% 处截断。验证集标签标准差 0.0755。

**没有做小波去噪。** 论文用 db4 对训练集去噪。全局小波滤波在分解-重构时用到了整段序列的信息，
训练段与推理段的分布会不一致；而要把它做成因果的（只用过去点），实现成本远高于它能带来的收益，
尤其在模型本身就没有信号的前提下。这是一个有意的省略，不是遗漏。

## 3. 模型

结构严格按论文表 3-1 实现，输入 `(N, 1, 7, 9)`：

```
Conv2d(1→16, 3×3, pad=1) → PReLU → MaxPool2d(1×1) → Dropout2d(0.2)
 → permute(0,2,1,3).reshape(N, 7, 144)
 → LSTM(144→32, 2 层) → LSTM(32→16, 1 层)
 → 时间维加性注意力 → Linear(16→8) → PReLU → Linear(8→1)
```

两处必须说明的偏差：

1. **MaxPool2d 用的是 1×1 核。** 论文表里池化层输出形状与输入相同，而 LSTM 的输入是 144 = 16×9 通道。
   只有 1×1 池化同时满足这两个约束。要么表写错了，要么池化根本没生效——我按"能产出所声明张量形状"
   的方案实现。
2. **参数量 35,027 vs 论文 34,729，差 298。** 按 `4·h·(in+h+1)` 算，两层 LSTM 应为
   30,976 + 3,136 = 34,112；论文写 31,232 + 3,200 = 34,432，分别多 256 和 64，恰好都是 `4·h·2` 与 `4·h·1`。
   这不像笔误，更像是把偏置或投影项重复计了一次。本仓库直接报 PyTorch 实数。

训练设置：Adam，初始 lr 1e-3，cosine annealing 到 1e-5，batch 128，MSE，梯度裁剪 1.0，
早停 patience 12。论文写初始 lr 0.1——在这个标签尺度下会在几步内发散，实测确认。

## 4. 结果

### 4.1 模型信号（样本外）

验证段 2025-06-26 起，12,759 个窗口，325 个交易日。

| 指标 | CNN-LSTM-Attn | Ridge 基线 | 判读 |
|---|---|---|---|
| 预测标准差 | 4.18e-06 | 1.1e-02 | CNN 输出了常数 |
| R²（vs 均值） | 0.0001 | — | 等价于不预测 |
| 方向准确率 | 49.74% | 50.00% | 与全猜涨的 49.74% 无区别 |
| 日频 IC 均值 | -0.016 | -0.0026 | 两者都≈0 |
| IC 标准差 | 0.289 | 0.249 | 噪声主导 |
| IC IR（年化） | -0.99 | -0.19 | \|IR\|<1，不显著 |
| 分层价差 D10−D1 | -1.50% | -0.83% | 排序没有单调性 |
| 高波动日 IC / 低波动日 IC | +0.004 / -0.070 | — | 无稳定结构 |

**CNN 塌缩。** 1.4 万条验证样本上预测标准差 4×10⁻⁶，注意力七步全 0.1428（均匀）。
它学到的唯一最优解是"输出训练集均值"。

**这不是调参问题。** 六组配置各自独立训练（40 epoch，早停 patience 12），验证方向准确率全部落在
49.51%–50.58%，预测标准差全部在 1e-4 以下：

| 配置 | 方向准确率 | 验证 MSE | 预测标准差 |
|---|---|---|---|
| 基线 lr 1e-3 / batch 128 / 窗口 7 / raw 标签 | 49.74% | 0.005697 | 4.2e-06 |
| lr 1e-4 | 49.74% | 0.005697 | 4.6e-05 |
| batch 256 | 49.74% | 0.005697 | 1.4e-09 |
| 窗口 20 | 49.51% | 0.005720 | 2.0e-07 |
| 特征换 `raw9`（原始 OHLCV） | 49.74% | 0.005697 | 2.0e-04 |
| 标签换 cross-sectional rank | 50.58% | 0.083240 | 3.1e-09 |

全猜涨的基准是 49.74%。也就是说**六组配置里没有一组偏离基准超过 0.9 个百分点**，
而且那个 50.58% 对应的是一个预测常数——不是它会挑，是那批样本里涨的略多。

**线性基线的作用。** 如果只有 CNN 失败，可以说"网络不行"。Ridge 在同样特征上有真实方差、
IC 仍然 -0.0026，说明特征本身不含这个尺度上的信息。这才是可信的归因。

### 4.2 策略

7 日调仓，全池做多，等权，含 8bps 手续费 + 2bps 滑点。

| 区间 | 信号 | 年化 | 夏普 | 最大回撤 | 等权持有同期 | 超额 vs 等权 |
|---|---|---|---|---|---|---|
| 2023-01 → 2024-12 | 动量 | 6.50% | 0.35 | -16.65% | 28.46% | **-21.96%** |
| 2023-01 → 2024-12 | 反转 | 2.72% | 0.12 | -25.24% | 28.46% | -25.74% |
| 2025-01 → 2026-10 | 动量 | 30.04% | 1.72 | -8.66% | 36.86% | -6.82% |
| 2025-01 → 2026-10 | 反转 | -7.31% | -0.52 | -19.10% | 36.86% | -44.17% |

同期沪深300：2023–2024 年化 0.63%，2025–2026 年化 3.90%。

**怎么读这张表。** 只跟指数比，动量策略"跑赢 5.87 个百分点"，看起来是个成果。
但同一批股票等权买了不动是 28.46%——策略跑输近 22 个点。指数只有 0.63%，
恰恰暴露了股票池的幸存者偏差有多严重：今天的 300 家公司在 2023–2024 期间
表现远好于当时的真实沪深300。

正确的结论是：**在这个池子、这个频率上，主动选股是负贡献。** 反转更差，说明
"短周期内买跌"也不成立。两者亏损的来源不同（动量输在换手，反转输在趋势），
但方向一致。

换手成本：年换手 42 倍，8.08% 的累计成本拖累 ≈ 4 个百分点/年。论文明确写了"未考虑交易税费"，
这相当于把策略最贵的一项成本划掉了。

### 4.3 为什么论文的 78.3% 复现不出来

不能断言原作者怎么算的，只能说：用同一套结构、同一批特征、严格的样本外切分，
得不到任何接近的数字。三个可能的来源，按可疑程度排序：

1. **在训练集上评估。** 训练 MSE 0.00497 / 验证 0.00570，两者都贴着标签方差，
   说明模型没有任何拟合能力可供"泄漏"到训练集上去刷分。单靠这一点解释不了 78.3%。
2. **准确率的定义不同。** 若把「预测值落在真实值 ±x% 区间内」算作准确，或对标签做了分类化
   再取多数类基线，数字可以大幅抬高。78.3% 更接近一个分类任务的指标，而本任务是回归。
3. **数据泄漏。** 若 MinMax 或标准化在切分之前对全量数据拟合，验证集信息会渗进训练——
   论文 3.2.2 节描述归一化时未说明统计量取自哪一段。

无论哪一种，结论都是：这个数字不能作为模型能力的证据。

## 5. 复现命令

```bash
python -m quantagent.cli fetch --workers 8
python -m quantagent.cli train --max-per-symbol 200
python -m quantagent.cli evaluate
python -m quantagent.cli backtest --start 2023-01-01 --end 2024-12-31
python -m quantagent.cli backtest --start 2025-01-01 --end 2026-10-28
python -m quantagent.cli backtest --start 2023-01-01 --end 2024-12-31 --signal reversal
python -m quantagent.cli tune --trials 40
```

产物：`reports/backtest.json`、`reports/signal.json`、`reports/equity_curve.svg`、
`reports/training_curve.svg`、`artifacts/train_summary.json`。

注意：日线数据每日变化，重跑的数字会与本文有微小差异（股票池快照固定，
但每只股票的最后一根 K 线会更新）。文中数字对应 2026-11-08 的数据快照。
