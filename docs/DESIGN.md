# 设计取舍

记下来的都是"本来可以这样，为什么选了那样"。

---

## 1. 取数：三级 fallback，而不是封装一个库

原方案是 `akshare`。实际用下来，问题不是 akshare 本身，而是它背后的上游：东方财富
`push2` 集群在被同一 IP 连续请求三次后开始返回 `RemoteDisconnected`，腾讯在约 900 次请求后
返回 501。封装库只会把这种失败包成异常，不会让它变少。

所以直接对着两个 HTTP 端点写：

- 腾讯 `web.ifzq.gtimg.cn`：日线主源，640 根/次，向前翻页。字段顺序是
  `[date, open, close, high, low, volume]`——**open 后面是 close 不是 high**，抄错这一列
  会得到一个走势看起来很合理、回测结果全是垃圾的系统。
- 新浪 `CN_MarketData.getKLineData`：指数序列 + 兜底，最多 1023 根，不复权。
- 东方财富：官方沪深300 成分股列表，只在股票池这一步用。

三级都失败才抛错，并且每次成功都落 parquet。**缓存是复现的边界**：
`data/cache/` 建立后，`train`/`backtest`/`evaluate` 全程零网络。

## 2. 股票池：市值前 300，而不是硬编码成分股

沪深300 的官方成分股半年调一次，历史时点的列表要付费或者爬中证指数官网。
两个选项：

- 硬编码一份 2026 年的 300 个代码 → 三个月后就有成分股退市/被调出，仓库悄悄过期。
- 每次取「A 股市值前 300」→ 规则可复现，但引入幸存者偏差。

选了后者，并且**把偏差量化出来放在 README 第一屏**（等权持有曲线）。硬编码那份名单看起来更
"正确"，实际是给未来的自己埋雷。

## 3. 回测：三条基准线，不是一条

只跟沪深300 比，几乎所有 A 股多头策略都"有超额"。所以每次回测都画三条：策略、指数、等权持有。

第三条是关键。它回答的是"如果我什么都不选，就买这个池子，会怎样"。2023–2024 那个区间里，
答案是 28.46%——策略的 6.50% 立刻从"跑赢指数"变成"严重跑输"。

一个只有一条基准线的回测报告，基本信息量接近于零。

## 4. 评估：IC 优先于 MSE

MSE 会被标签方差淹没。同样的 0.0057，在一个方差 0.083 的标签上和在 0.0057 的标签上是两件事。
所以主指标是：

- **日频横截面 IC**（Spearman）：每天在股票之间排个序，看它和实际收益排序的相关性。
- **分层收益**：按预测值分十组，看 D10 减 D1 是不是正的、是不是单调。
- **IR**：IC 均值 / IC 标准差 × √天数。|IR| < 1 就是噪声。
- **退化检测**：预测标准差 < 1e-4 直接标记 collapsed，不再输出花哨的相关系数。

这套指标不宽容。它的作用就是把"看起来很厉害的模型"和"其实什么都没学到"分开。

## 5. Agent：无 key 也能跑

两个模式共用一个工具注册表：

- LLM 模式：任意 OpenAI 兼容接口，函数调用循环，最多 6 步。
- 本地规划模式：关键词 + 正则路由到工具，把返回值渲染成中文结论。

做本地模式不是为了炫技，是因为**一个 clone 下来必须先申请 API key 才能看到任何东西的仓库，
大多数人不会看完**。现在 `make serve` 就能问"600519 未来一周怎么样"，只不过回答是模板拼的。

系统提示词里最长的部分是数据来源约束，不是角色设定。原因：LLM 压在后测之上，
最典型的失败不是答错，是自信地叙述它编造的数字。

## 6. 前端：单页 + 手写 SVG

没有 React，没有 ECharts，没有构建步骤。三个原因：

1. 图表只有四种（K线、折线、柱状、净值），手写 200 行 SVG 比引入一个 300KB 的库更短。
2. 仓库里没有 `node_modules`，评审者 `git clone` 之后不需要 `npm install` 就能看到界面。
3. 图表本身就是论证的一部分——"策略 vs 等权"那条线要足够显眼，用默认主题反而达不到。

代价是没有交互（缩放、tooltip、hover）。对研究演示够用，对产品不够。

## 7. 没做的

- **walk-forward 滚动验证**：只切了一刀 80/20。正确做法是每半年重训一次、滚动预测。
- **涨跌停 / 停牌撮合**：实盘里 7 日调仓打到涨停板买不进，回测里照买不误。
- **BERT 情感分支**：没有稳定的中文财经新闻源，且数值分支本身无信号，融合没有意义。
- **K8s / Redis / RabbitMQ**：单机研究工具，这套编排的运维成本比计算本身高三个数量级。
